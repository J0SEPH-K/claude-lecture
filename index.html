# 주간 업무 보고 작성법
## 순서
1. 이번 주 한 일, 다음 주 할 일, 문제점을 받는다. 빠지면 먼저 묻는다.
## 양식
- 제목: [팀명] 주간 업무 보고 (MM/DD ~ MM/DD)
- 1. 핵심 성과 (최대 3개, 숫자 포함)  2. 진행 중인 일 (표)
- 3. 문제와 도움 요청  4. 다음 주 계획
## 규칙
- 첫 줄에 한 문장 요약 (팀장님이 첫 줄만 읽으시니까)
- 사용자가 주지 않은 숫자는 [확인 필요]

004 — 가장 중요한 한 줄

Claude는 스킬 설명(description) 한 줄만 보고 꺼낼지 정합니다

✕ 나쁜 설명

"보고서 스킬"

언제 쓰는지도, 무엇을 하는지도 없음.

✓ 좋은 설명

"사용자가 주간보고, 주간 업무 보고, 금주 실적 정리를 요청할 때 사용. 우리 팀 양식으로 A4 한 장 보고서를 쓴다."

언제 쓰는지 + 무엇을 하는지를, 사람들이 실제로 쓰는 단어로.

004 — 좋은 스킬의 5가지 조건

  1. 한 스킬 = 한 가지 일보고서 + 메일 + 회의록을 한 스킬에 넣지 않기
  2. 순서는 번호로신입사원이 따라 할 수 있게
  3. 이유를 붙이기"첫 줄 요약 (팀장님이 첫 줄만 읽으시니까)"
  4. 잘된 예시 하나가설명 열 줄보다 낫다
  5. 써 보고 고치기결과가 이상하면 바로잡는 규칙을 한 줄씩 추가

006 — 전체 흐름 · → 키로 한 단계씩

  1. 규칙은 내가 정합니다. 과제와 판단 기준을 심사위원장에게.
  2. 똑같은 과제를 10명에게. 단, 해법은 한 명당 하나씩 모두 다르게.
  3. 근거로 토론. 출처 없는 주장은 기록에서 삭제.
  4. 심사위원 3명이 전부 듣는다. 서로 상의하지 않는다.
  5. 각자 최고 1명 + 이유를 심사위원장에게 보고.
  6. 최종 1개. 내가 준 기준 그대로 적용.

에이전트를 클릭하면 발언합니다

006 — 역할 4가지

① 나

과제 + 판단 기준

② 심사위원장

배분 · 최종 선택

③ 에이전트 10명+

같은 과제, 다른 해법

모든 주장에 최신 자료와 출처·날짜. 다른 안은 근거를 들어 반박.

④ 심사위원 3명

독립 심사

상의 금지. 각자 1명 선택 + 기준별 이유. 출처가 부실하면 감점.

008 — API (개발자에게 전달)

import anthropic

client = anthropic.Anthropic()  # 키는 환경변수에

answer = client.messages.create(

)
print(answer.content[0].text)

🧰 도구함

내가 맡고 있는 "[업무 이름]"을 나 없이도
누군가 똑같이 해낼 수 있도록 나를 인터뷰해 줘.

  → 판단 기준 → 자주 하는 실수 → "완료"의 기준 → 예외
- 답이 애매하면 구체적인 예를 다시 물어봐.
- 충분하면 "인터뷰 완료"라고 말해.

🔁 실수하면?

대화로 고치지 말고, 그 업무의 매뉴얼을 고친다

대화로 고치면 다음에 또 틀립니다. 매뉴얼을 고치면 다음부터 계속 반영됩니다. 시스템 전체가 아니라 그 매뉴얼 한 권만.

인터뷰 → 매뉴얼 → 도구함 → 검증 → 실행 → 틀리면 매뉴얼 수정. 이게 전체 순환 과정(루프)입니다. 반복 업무는 위임, 중요한 결정은 토론회.
