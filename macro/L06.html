0:20 — 시작 전에 규칙 다시

RULES.

연습 게임과 실제 게임의 차이

실제 게임에서는 규칙을 어기면 계정이 정지될 수 있고, 되돌릴 수 없습니다.

101 — 규칙과 매뉴얼을 Claude에게 대조시키기

CLAUDE.md의 게임 규칙과 docs/작업 매뉴얼 - (작업 이름).md를 읽고,
이 작업이 규칙 안에 있는지 확인해 줘.
- 허용된다면 어느 규칙 문장에 근거하는지 알려 줘.
- 애매한 부분이 있으면 무엇이 애매한지 알려 줘. (예: 자리 비움 중 사용, 반복 횟수 제한)
- 규칙이 마지막으로 바뀐 날짜를 내가 직접 확인해야 하는지도 알려 줘.
근거

"허용"이면 어느 문장 때문인지

애매하면

운영사 공지·고객센터 답변이 최종 기준

금지면

오늘은 연습 게임으로, 다른 작업을 찾기

0:40 — 게임 설정 고정

SETUP.

게임 화면을 늘 같은 모습으로

증명사진으로 사람을 찾는데 상대가 두 배로 커지면 못 알아봅니다. 그림 찾기도 같습니다.

201 — 자동화가 안정되는 게임 설정

화면 모드

창 모드

또는 테두리 없는 창. 전체 화면은 사진이 까맣게 나오기도

해상도

하나로 고정

예: 1280x720 · 1920x1080

윈도우 배율

가능하면 100%

125%·150%면 좌표가 어긋나기 쉬움

창 위치

늘 같은 자리

where.py로 왼쪽 위 모서리 확인

UI 크기·밝기

그대로

바꾸면 그림을 다시 찍어야 함

202 — 정한 설정을 매뉴얼에 기록

작업 매뉴얼의 "시작 전 화면 상태와 게임 설정"에 아래 설정을 기록해 줘.
- 화면 모드: (창 모드 / 테두리 없는 창)
- 해상도: (예: 1280x720)      - 윈도우 배율: (예: 100%)
- 게임 창 왼쪽 위 모서리: (x, y)  ← where.py로 확인한 값
- UI 크기·밝기: 기본값, 바꾸지 않음
그리고 완료 체크리스트에 "게임 설정이 매뉴얼과 같은가? (내가 확인)"을 추가해 줘.
"설정이 바뀌면 그림과 좌표를 다시 확인한다"도 '자주 생기는 실패와 대처'에 적어 줘.

⚠️ 윈도우 배율을 바꿨다면 로그아웃 후 다시 로그인하고, 어제 찍은 그림이 맞는지 4번에서 시험합니다.

1:05 — 입력이 게임에 닿는지

INPUT.

눌러도 손해가 없는 키 하나로 먼저

많은 게임은 DirectX 방식으로 키를 받아서, 일반 키 입력을 무시하기도 합니다.

301 — 시험용 input_test.py

input_test.py를 만들어 줘. 게임이 우리 매크로의
키 입력을 받는지 확인하는 시험용이야.
- 실행하면 5초 카운트다운. 그동안 내가 게임 창을
  클릭해서 맨 앞으로 가져올게.
- 카운트다운이 끝나면 (키 이름) 키를 딱 한 번만 누르고 끝나.
- 키 입력은 screen.py의 press를 써.
- screen.py가 pydirectinput을 먼저 쓰고, 없으면 pyautogui를
  쓰는지 확인해서 알려 줘. 아니면 그렇게 고쳐 줘.
  설치돼 있지 않으면 설치 전에 물어봐. (pydirectinput-rgx)
해가 없는 키

지도 M · 인벤토리 I

열리면 통과. 공격·구매·판매 키로는 시험하지 않습니다.

302 — 키가 안 먹을 때: 이 순서대로

순서확인할 것어떻게
① 맨 앞게임 창이 맨 앞에 있었나?카운트다운 동안 게임 창 클릭
② DirectXpydirectinput으로 보내고 있나?Claude에게 확인시키기
③ 관리자게임이 관리자 권한으로 실행되나?매크로도 관리자 PowerShell에서 실행
(Claude Code는 일반 창 그대로)
④ 멈춤그래도 안 먹음 · 경고가 뜸게임이 막는 것 → 우회하지 않고 멈춤

관리자 권한 차이는 게임의 보호 장치가 아니라 윈도우의 기본 규칙입니다. 게임 안에서 F8·F12가 안 먹을 때도 같은 원인일 수 있습니다.

403 — 계획 모드(Shift + Tab)로 시나리오 v1

docs/작업 매뉴얼 - (작업 이름).md를 읽고,
그 작업을 하는 scenario_game.json을 만들어 줘. scenario.py는 고치지 마.
- 매뉴얼의 처리 순서를 그대로 단계로 옮겨. 그림은 templates 폴더의 것을 써.
- 기다리는 단계마다 매뉴얼에 적힌 시간 제한을 넣어.
- 처음 시험이니까 loops는 1, 재시도는 1.
- 단계마다 왜 그 단계가 필요한지 한 줄씩 설명해 줘.
- 다 만들면 매뉴얼의 완료 체크리스트로 확인하고 결과를 표로 보여 줘.
계획을 먼저 보여 줘.
