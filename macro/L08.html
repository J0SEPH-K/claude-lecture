101 — 최종 점검표

점검 항목확인하는 법
① 10번 연속 성공반복 횟수 10 → 기록에 실패 0번
② F8 멈춤 → 이어짐멈춘 자리부터 다시 시작하는지
③ F12 · 정지 버튼각각 1~2초 안에 끝나는지
④ 왼쪽 위 구석마우스를 밀면 멈추는지 (FAILSAFE)
⑤ 실패하면 깔끔히 멈춤일부러 실패시켜도 엉뚱한 곳을 계속 누르지 않는지
⑥ 기록을 내가 읽음Claude 없이 "몇 회차, 몇 번째 단계, 왜"를 말할 수 있는지
⑦ 지금도 규칙 안최신 이용약관 · 운영 정책 = CLAUDE.md의 게임 규칙

## 버그 보고
- 하려던 일: (예: 일일 보상 받기 시나리오)
- 실제로 일어난 일: (예: 3번째 단계에서 계속 실패하고 멈춤)
- 기대한 일: (예: 보상 버튼을 찾아 클릭)

- 몇 번 중 몇 번: (예: 10번 중 7번)

- 실패 화면 파일: (예: logs/20261129_101500_step3_find_click.png)
- 최근에 바뀐 것: (게임 업데이트, 화면 배율, 내가 고친 파일, 없음)

402 — CLAUDE.md를 오늘 기준으로 정리

CLAUDE.md를 오늘 기준으로 정리해 줘. 짧고 읽기 쉽게.
1. 이 프로젝트의 목적과 게임 규칙(허용 범위, 금지 사항)
2. 파일별 역할 한 줄씩 (조종판, 엔진, 화면 도구, 시나리오, 템플릿 폴더, docs)
3. 작업 매뉴얼, 유지보수 매뉴얼, 버그 보고 양식이 어디 있는지
4. 고칠 때 순서: 버그 보고 → 원인 후보 → 계획 → 고치기 → 매뉴얼 반영
   → 1회 확인 → 10회 점검 → 커밋
5. 안티치트 회피, 메모리 읽기·조작, 게임 파일 변조는 하지 않는다
이미 있는 규칙(한국어 주석, 설치 전에 묻기 등)은 지우지 말고 유지해.

검증: /clear → 새 대화에서 요약을 받아 보고, 틀린 곳이 있으면 그 자리에서 고치기

502 — 두 번째 작업 시작하기

두 번째 작업 "(작업 이름)"을 추가하고 싶어. 새 프로그램은 만들지 마.
먼저 CLAUDE.md의 게임 규칙에 비추어 이 작업이 허용 범위 안인지 확인해 줘.
허용 범위 안이면, 작업 매뉴얼을 만들 때처럼 나를 인터뷰해 줘.
- 질문은 한 번에 1~2개씩
- 순서: 목적 → 시작 화면 → 단계별 순서 → 단계마다 무엇이 보이면 성공인지
  → 자주 생기는 실패 → '다 됐다'고 볼 기준
인터뷰가 끝나면 docs/에 작업 매뉴얼을, 새 작업 폴더에 시나리오 파일을 만들어 줘.
지금 엔진에 없는 단계 종류가 필요하면, 만들기 전에 나에게 먼저 말해 줘.

엔진에 기능을 더했다면 → 첫 번째 작업도 10회 점검 다시
